数据库增量脚本建议执行顺序（在导入基线 wxfbsir.sql 之后）
================================================================

说明：
- 基线文件：wxfbsir.sql（首次建库）
- 下列脚本按日期/依赖关系排序；新环境漏执行会导致运行期 Unknown column 等错误

建议顺序：
0. （推荐、一条搞定旧基线缺列）update_20260421_对齐wc_chat_history与ws_host_whitelist基线_幂等.sql
   - 幂等 ADD COLUMN：wc_chat_history.gitee_chat_id、ws_host_whitelist.host_type/health_check_url/online_status
   - 若此前已执行过下面 1+2，执行本脚本只会输出 skip，无影响
1. update_20260129_插入giteeAI助手.sql
   - 为 wc_chat_history 等补充 gitee 相关字段/数据（与 AIGC Mapper 一致）
   - 已被合并入当前 wxfbsir.sql 基线；仅「从未执行过增量」的旧库需要；亦可由 0 替代本项
2. update_20260316_为白名单表添加在线状态，主机类型，健康检查字段.sql
   - Engine 注册/白名单能力所需列（整表 DROP+CREATE，慎用：会清空白名单自定义数据）
   - 增量升级更推荐 0（仅补列）；新装请直接导入已合并的 wxfbsir.sql
3. update_20260303_新建系统提示词表和Webhook地址表.sql（若使用输出物/Webhook 能力）
4. update_20260321_输出物权限.sql（菜单与权限）
5. 其余按业务需要执行（如 update_20260414_*）
6. update_20260418_wc_playwright_draft_user_id.sql
   - wc_playwright_draft 增加 user_id 列、回填、索引（与 AigcMapper 草稿双写一致）
   - 若建库已使用「合并后的」当前 wxfbsir.sql（表内已有 user_id 与 idx_user_id），则**勿再执行**本脚本，否则会 ADD COLUMN / CREATE INDEX 失败；仅对「自旧基线升级、尚无 user_id」的库执行。

基线合并说明：
- 当前 wxfbsir.sql 已含：wc_chat_history.gitee_chat_id；ws_host_whitelist.host_type / health_check_url / online_status；wc_playwright_draft.user_id（等）。对应单项增量可跳过；以 INFORMATION_SCHEMA 为准。
- 若曾用手工 ALTER 把 online_status 建成 tinyint，与 Java 实体 String 不一致，建议改为 varchar（可备份后 ALTER TABLE ... MODIFY COLUMN）。

MySQL 版本：
- AIGC 草稿列表等查询使用 ROW_NUMBER() 窗口函数，需 MySQL 8.0+，且开启 ONLY_FULL_GROUP_BY 时应使用已合并的聚合写法（见 AigcMapper.xml）。
